# 面向未知问题的语义信道编码 Agent

## 目标与状态

长期原则：**兼顾分数和创新性，要尽可能调用大模型来解决问题，不要为了调用而调用，而是通过大模型提升 Agent 的能力。** 用户确认默认采取更激进的综合分优化，接受小幅 q 波动；这不放宽来源、事实和通信规则。

最新正式自动报告 `eval-20261107-720b6325` 为 52.3/100、q=97.8%，但提交版本未知；正确率/时间/压缩/通信分分别为 29.2/3.1/1.2/18.7。最近可确认提交的报告 `eval-20261107-920cc006` 对应 `0510c1a`：53.1/100、q=97.2%，分项分别为 28.9/3.1/2.1/19。两轮均有 87 次 Gateway 调用，最终 B 仍长、耗时较高。

本地详细规则中的评分公式为 `S=q*(30+10FT+30FB+30FD)`。按 `q=.972`、`FT=.60`、`D/A=.25` 估算，达到 80 分需要 `B/A` 约不高于 15%；若 q 降至 .92，则同样效率指标约为 75.6 分。该计算仅用于设置联合工程目标，不代表平台结果或可保证的上限。新实现待正式评测；应同时关注 q、B/A、D/A、T 与失败率。

上一轮 `0510c1a` 比 `912df46` 多 45 次 Gateway 调用，但只提升 3 分，时间项下降 2.5 分，压缩项只提高 0.1 分。因此模型调用按价值设计，而不是追求次数：Sender 负责在本例 A 上形成可核对的语义编码；Receiver 只基于实收编码生成最终 B。程序负责字节预算、摘要校验和截止调度，模型负责事实表达和审阅。

## Sender：来源约束的语义编码

1. 默认 `SEMANTIC_MODE=aggressive`。文章达到 1024 字节后，Sender 把本例 A 划成最多三个有上下文的连续区段，并行请求统一模型，将叙事转成事实账本、时间线、比较或关系短句。每段以约 30% UTF-8 字节作为提示目标，要求保留实体与角色、动作、日期、数值和单位、归属、因果、否定、条件、例外和不确定性。
2. Sender 将区段结果合并，再调用独立模型对照完整 A 审阅。程序把归一化后的数字缺口交给审阅模型，并检查新增数字和否定表达，验证修复引用确实来自 A，测量信封与实际 UDP 传输计划字节。当前编码结果至少需要约 30% 的净负载收益；未达门槛、内容无效、模型失败或编码预算耗尽时回退原文。
3. 编码与审阅最多使用当时剩余截止预算的 40%，为传输、接收端解码和最终锁定留下时间；这不是固定的全局超时。`lossless` 模式跳过 Sender 语义编码，直接传原文，作为消融基线。
4. 语义记录仍通过和原文相同的 UDP 中继、分块摘要、全文哈希和 ACK 机制传输。Receiver 收到的记录是实际传输来源，不能通过 HTTP、文件、环境变量或模型侧信道补回 A。

编码记录不是隐藏题的预测答案或题库专用解法。独立模型审阅可以发现一部分遗漏和关系失真，但不保证完整性；保留多少细节以及编码预算都需要用正式 q 和效率分项评估。

## Receiver：全局压缩与独立审核

Receiver 只使用弱网实际收到并校验的 UDP 数据。传输完整时验证信封、块哈希和全文摘要；部分接收时只根据已验证区段重建，明确标记缺失范围，不推断缺失事实。Receiver 正常成功仍需产生可核验的统一模型调用。

正常成功路径只需要两个有明确职责的模型阶段：

- 全局压缩角色对整个实际收到的来源生成账本，使用约 24% UTF-8 字节作为目标提示，合并跨段重复的实体、单位和背景，同时保留关系与限定。
- 独立 critic 对照实际收到的完整来源检查候选；修复必须引用真实原文，程序检查新增数字和否定表达。程序只在审核通过且候选仍有字节收益时接受。

紧凑候选生成阶段最多使用当前可用模型预算的 55%，核验阶段最多使用余下预算的 65%，保留后续处理空间。如果候选不够短、critic 拒绝、超时或调用失败，才退回 `generate_record` 的忠实分段/覆盖流程。若忠实兜底也无法获得完整模型覆盖，就返回失败状态，不将原文或程序拼接内容伪装为模型结果。

数值检查先做 Unicode 和数值归一化，减轻日期分隔符、千位逗号、小数格式等表达差异造成的误拒。缺失的数字列表作为审阅提示，而非逐一硬性保留：模型需要区分事实数值与编号、重复或无关数字，并修复实质性遗漏。这能减少字节门槛对压缩的阻碍，但可能放过模型漏判的数值遗漏；否定和新增数字检查也不能证明语义完整或 q，正式正确率由隐藏题判定。

## 时间与失败

- 所有路径共用最初 `/send` 接受时刻和平台截止，META 仅携带实时剩余预算，不能因传输重试或模型处理重新获得完整时限。
- 必需生成使用真实截止预算；可选紧凑核验与补丁受剩余时间限制。不会将 70/40 秒写死为所有调用等待上限，也不会取消长首调后用很少余时从头重做。
- 任务预留 8 秒用于结束真实 task/session、Trace flush 和平台轮询，成功只在 flush 后公布。健康接口报告真实遥测配置，不调用模型。
- 缺片时可基于已验证部分来源开始模型恢复，不能推断缺失内容；随后收到完整且哈希有效来源时可尝试改进，晚到改进失败保留已经完成的有效模型结果。
- 模型响应必须正常 `stop`，空输出、截断响应、未经核验候选和原文直接照抄不能作为正常成功 B。全部模型都失败或 Gateway 阻塞到截止时，仍可能没有可锁定 B。
- `SEMANTIC_MODE=lossless` 关闭 Sender 语义编码；Receiver 自适应模型流程仍运行。旧 `refine_record` 保留作离线对照，不在默认任务路径中执行。

## 内容与证据边界

- 所有来源内容只经赛事 UDP 中继跨端传输；各端统一模型调用彼此独立，不用模型服务状态传递另一端信息。
- 原文若以保留前缀 `SCNSEM1` 开头，会用带 `semantic:false` 的信封转义，避免被误作控制元数据；信封不成为最终 B。最终只输出 UTF-8 明文事实记录 `reconstructed.content`。
- 不预存题库文章、隐藏问题、答案或跨任务事实。不连接公网或未经授权的外部服务，不修改网络规则，不使用特权能力或旁路。
- 两端仍使用官方 AMD64 基础镜像、非 root；所有模型调用读取平台注入配置，处于真实 AgentRuntime session/task 并产生真实 Trace。Receiver 正常成功必须有可核验成功模型调用，不能用规则程序代替。
