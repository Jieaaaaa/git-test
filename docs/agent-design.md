# 面向未知问题的语义通信 Agent

## 目标与证据

长期原则：**兼顾分数和创新性，要尽可能调用大模型来解决问题，不要为了调用而调用，而是通过大模型提升 Agent 的能力。** 允许小幅 q 波动，以综合分为目标；模型调用数量不是独立目标。所有事实必须来自本例实际输入，规则边界不因提分目标放宽。

最新正式报告 `eval-20261108-50c8d34a` 对应 `3eadc2b`：39.4 分、q=60%。OA01 三档 q=100%、单例最高 73.09，表明短表达有收益；但 OA02-medium/bad q=30%，OA03-good 无 B，OA03-bad 有 B 而 q=0。平台未开放原始 B 与日志，不能把代码风险直接断言为各例根因。完整记录见 [评测档案](evaluations.md)。

当前最高已知完整分仍是 `0510c1a` 的 53.1。新候选尚无正式分，不承诺达到 80。由 `S=q*(30+10FT+30FB+30FD)` 可知，q=.972、FT=.60、D/A=.25 时，80 分要求 B/A 约不超过 15%；不能只靠改短 B 或减少调用解决全部问题。

## 决策流程

```text
Sender：本例完整 A -> 选择实际帧成本最低的无损编码 -> 受控 UDP
Receiver：验证分块和全文哈希 -> 并行理解实收来源
  全局紧凑模型 -> 独立来源审阅 -> 接受 / 引用修复 / 拒绝
  分段事实模型 + 独立全文覆盖模型 -> 完整覆盖候选
根据已完成候选、审阅结果、字节测量与剩余预算选择 B
结束 task/session -> flush 真实 Trace -> 发布 reconstructed.content
```

模型负责理解、选择账本/时间线/关系短句、解析跨段指代、事实查漏与修复；程序负责测量、完整性、并发调度、截止和结果保留。候选竞争用于提高完成性与压缩质量，不产生隐藏题或预测答案。

## Sender 与无损传输

默认 `SEMANTIC_MODE=lossless`，不等待发送端模型。完整来源立即经 UDP 发送，避免不可逆的信息损失与两端模型串行。这里的 lossless 只描述传输，最终 B 仍必须由统一模型生成。

传输工具比较小片以及 4/8/16 KiB 独立块方案，逐块比较 raw、zlib9、bz2 level1、lzma2，再按实际帧、元数据和 ACK 字节选最低计划成本。lzma 字典为 64 KiB，解压内存上限 2 MiB；bz2 只接受小内存块头。解压输出限制为声明长度加一，并拒绝截断、尾随、拼接流和摘要不符。各块 SHA-256 摘要、整篇 SHA-256、帧 CRC 和独立部分恢复保留。

选择性重传采用累计 ACK，反馈丢失时先重新查询再补发数据。每帧最多 1400 字节；Sender/Receiver 发送预算为 15/1 MiB。计划估计不包含未知的实际丢包重传，不能视作官方 D。

`SEMANTIC_MODE=aggressive` 保留为显式实验：Sender 分段模型编码加独立来源核验，最多使用当时剩余截止时间的 40%，比较实际传输收益后采用，失败则原文传输。本轮默认关闭；如果启用，Receiver 对实收编码只做忠实规范化，不再按其 24% 生成第二轮摘要。

## Receiver 的候选与审阅

Receiver 同时启动两个路径：全局模型以约 24% 原文 UTF-8 字节为表达目标；独立事实覆盖流程以约 35% 为目标，最多三个连续区段并行生成，并配独立全文覆盖草稿。目标是提示，不是硬截断，也不允许丢掉独特事实换长度。角色保留实体全称与显式别名、动作关系、日期、数值及单位归属、因果、比较方向、否定、条件、例外、不确定性与失败的替代方案。

紧凑候选完成后，critic 对照完整实收来源核验。若此时独立覆盖草稿已完成，将其作为查漏提示一并提供，但来源仍是唯一依据。修复要带确实存在的原文引用，替换目标须唯一；程序还检查新增数字和否定。数字集合不能判断实体与数值交换，也不能证明事实完整，因此将这些对应关系明确交给模型检查。

critic 接受或完成有效修复后使用紧凑候选；显式拒绝或无效修复则不发布该候选。若审核挂起、紧凑候选无效或调用失败，独立覆盖已经在运行，优先使用其完整模型输出。只在覆盖也失败、审阅不可用且完整紧凑草稿通过数字/否定基础检查时，才允许保留未审阅草稿；这不代表其语义正确。所有模型失败、只有截断输出或原文照抄时仍失败，不以原文或规则提取内容冒充模型生成的 B。

## 时间与完成性

每例使用最初接受时刻的真实截止，重复 META 只能收紧，不能续期。模型预算始终扣除 8 秒收尾，不将 70/40 秒固定为全局调用上限。

紧凑生成最多使用初始可用模型预算的 65%；覆盖路径使用 88%，选择路径最多到 92%。覆盖候选完成后，最多再等待初始模型预算的 18% 争取审阅结果，随后取消慢请求并返回已有覆盖。覆盖流程内部，完整全文备用结果出现后只等待初始预算的 8%（且不超过剩余预算的 20%）收敛慢分段。各比例均随真实剩余时间变化，不是在可用结果出现后继续等到平台截止。

缺片时只能基于已验证范围恢复并标记缺失，不推断空白。已有部分 B 时，晚到完整来源的升级最多使用剩余模型预算的一半，受独立较早截止和外层取消约束；升级失败保留已完成 B。没有部分 B 时，仍允许完整来源使用剩余恢复预算。

SDK 只接受非空且 `finish_reason=stop` 的完整输出。长度截断可在同一请求绝对预算内扩大上限重试一次；仅快速连接/服务失败作有限重试。成功须在 task/session 关闭、真实 Trace flush 后公布；健康检查不调用模型。

## 验证与边界

105 项 AMD64 容器测试及四类本地 SDK/UDP 闭环覆盖正常、显式 aggressive、审阅拒绝并丢失数据/ACK、60 秒审阅挂起。自行生成的文章与模型桩只能验证工程流程，不能证明官方 q、压缩率、Token、Gateway 延迟或总分，详情见 [本地验收](local-validation.md)。

两端基于官方 AMD64 镜像，以非 root 启动。文章只经赛事 UDP 中继跨端传输；模型读取运行时注入的授权配置并产生真实任务调用。镜像不含文章、隐藏问题、答案、开发密钥或模型桩；不使用外部模型、模型侧信道、共享文件、特权或网络规则修改。原文若以保留前缀开头，先转义信封；最终 B 为独立可读 UTF-8 文本，不包含压缩码或信封。

下一轮正式报告应对比同文章/信道的 q、B/A、D/A、T 和成功率，尤其检查 OA02 的事实丢失与 OA03 的两类失败。只有正式综合分改善才能确认本轮方案有效。
