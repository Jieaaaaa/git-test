# 面向未知问题的语义通信 Agent

## 目标与证据

最新报告 `eval-20261108-c5f53cb5`：55.9分，q97.2%，9/9无异常，为当前最高完整分。以下历史段落保留前轮设计背景；本轮改变全局生成与审阅：直接生成约28%字节目标的纯文本报文，按实体/事件合并字段，避免 JSON 与过多主语标签。来源审阅取消强制 checks 数组，仅输出 accept/repair/reject、修复及真实来源引文，继续检查全部数字缺口、工具列出的否定条款和表头列数。保留并行分段检查点、合并冲突拒绝及截止回退。这一取舍减少非事实格式失败带来的长文回退，但仍有模型漏审风险，实际总分以新平台报告为准。

长期原则：**兼顾分数和创新性，要尽可能调用大模型来解决问题，不要为了调用而调用，而是通过大模型提升 Agent 的能力。** 允许小幅 q 波动，以综合分为目标；模型调用数量不是独立目标。所有事实必须来自本例实际输入，规则边界不因提分目标放宽。

最新正式报告 `eval-20261108-cbb7d6db` 对应 `5053eaa`：43.9 分、q=76.1%。七个有 B 的用例 q 为 90%–100%，但 B/A 为 62.4%–93.8%；OA03-good/bad 分别已有 3/4 次 Receiver 成功调用，却仍没有可锁定 B。成功调用不等于完整候选已可发布，平台未开放原始输出与日志，不能断言个例的具体失败阶段。完整记录见 [评测档案](evaluations.md)。

当前最高已知完整分仍是 `0510c1a` 的 53.1。新候选尚无正式分，不承诺达到 80。由 `S=q*(30+10FT+30FB+30FD)` 可知，q=.972、FT=.60、D/A=.25 时，80 分要求 B/A 约不超过 15%；不能只靠改短 B 或减少调用解决全部问题。

## 决策流程

当前采用分区策略：按约1,200字符、最多3区划分连续来源；每区模型直接生成约28%字节目标的报文，并独立进行来源审阅。各区有独立别名前缀和短上下文。生成前的工具检查表列出该区否定/例外，帮助模型保留容易遗漏的非数字边界。备用400字符事实包在相同分区内部划分、每区最多8段，仍由4个worker处理。候选检查点按原文区间次序拼接：已审阅紧凑结果优先，否则采用该区已完成事实包；单区失败或挂起不会清掉其他区的压缩结果。最多3路紧凑生成及审阅相互独立，避免先等整篇长输出再开始所有审阅。分区可能减少跨区共享规则的去重收益，最终仍须比较总分。

下图为此前整篇候选路径，保留作变更背景；当前实现以本节上述分区策略为准。

```text
Sender：本例完整 A -> 选择实际帧成本最低的无损编码 -> 受控 UDP
Receiver：验证分块和全文哈希 -> 并行理解实收来源
  全局模型选择表格/共享规则/账本 -> 分来源范围核验 -> 接受 / 引用修复 / 拒绝
  短分段模型 -> JSON 事实组 -> 每完成一段就保留候选
优先采用有效来源审阅结果，失败或到达收敛边界时保留已完成模型事实
结束 task/session -> flush 真实 Trace -> 发布 reconstructed.content
```

模型负责理解、选择账本/时间线/关系短句、解析跨段指代、事实查漏与修复；程序负责测量、完整性、并发调度、截止和结果保留。候选竞争用于提高完成性与压缩质量，不产生隐藏题或预测答案。

## Sender 与无损传输

默认 `SEMANTIC_MODE=lossless`，不等待发送端模型。完整来源立即经 UDP 发送，避免不可逆的信息损失与两端模型串行。这里的 lossless 只描述传输，最终 B 仍必须由统一模型生成。

传输工具比较小片以及 4/8/16 KiB 独立块方案，逐块比较 raw、zlib9、bz2 level1、lzma2，再按实际帧、元数据和 ACK 字节选最低计划成本。lzma 字典为 64 KiB，解压内存上限 2 MiB；bz2 只接受小内存块头。解压输出限制为声明长度加一，并拒绝截断、尾随、拼接流和摘要不符。各块 SHA-256 摘要、整篇 SHA-256、帧 CRC 和独立部分恢复保留。

选择性重传采用累计 ACK，反馈丢失时先重新查询再补发数据。每帧最多 1400 字节；Sender/Receiver 发送预算为 15/1 MiB。计划估计不包含未知的实际丢包重传，不能视作官方 D。

`SEMANTIC_MODE=aggressive` 保留为显式实验：Sender 分段模型编码加独立来源核验，最多使用当时剩余截止时间的 40%，比较实际传输收益后采用，失败则原文传输。本轮默认关闭；如果启用，Receiver 对实收编码只做忠实规范化，不再按其 24% 生成第二轮摘要。

## Receiver 的候选与审阅

Receiver 同时启动两个路径。全局模型以约 24% 原文 UTF-8 字节为表达目标，自主选择共享规则加实体行、时间线或关系账本；共用字段、列名和单位只声明一次，例外另列，避免把紧凑表达重新扩写成叙事。分段模型以约 30% 字节为目标，将来源按约 400 字符分成最多 24 个连续区段，以 4 个 worker 处理；优先靠近段落或句子边界，保留全部来源字符，避免一段挤入多个完整实体后只编码第一个。标题及相邻短上下文仅用于指代消解，不重复编码。目标是提示，不是硬截断，也不允许丢掉独特事实换长度。两个路径均须保留实体全称与显式别名、动作关系、日期、数值及单位归属、因果、比较方向、否定、条件、例外、不确定性与失败的替代方案。

模型输出严格 JSON 事实组，由 `fact_ledger.py` 校验和渲染为可读文本。分段每完成一次就更新检查点，按来源顺序合并；程序只合并完全相同主体、删除同主体下完全相同的事实，不做语义改写或生成事实。单段挂起不抹掉其他已完成结果，但使用不完整分段候选仍有事实缺失风险。

紧凑候选完成后，最多 3 个 critic 分别对照连续来源范围并行核验整份候选，重点检查实体与数值绑定、合取前提、否定和例外。全文仅作为上下文，当前范围是修复依据，不能把其他范围的候选事实误判为编造。审阅使用短补丁，避免重写整张表；表头与数值行可分别引用真实子串，不允许拼接出并不存在的引文。审阅须解释剩余数字缺口，修复和核验检查须引用真实来源与候选子串；这些结构检查不能证明语义完整。

工具从来源中标出否定及例外条款，按候选的文字覆盖度优先列出最多 6 项强制检查，重复数字模板去重。模型须对每项 ID 提供实际候选证据，缺失时先补回；单独数字不能证明条件。工具同时报告共享管道表头和数据行的列数不一致，不推断或代填事实。引用、列数等校验失败时，将具体工具错误和前次回答交给模型反思修正一次，共用原截止；显式 reject 不重试。这是有限的错误反馈循环，仍可能漏掉改写后的语义错误或未被列入检查的事实。

`merge_grounded_reviews` 将每份修复相对原始候选校验，再按原始位置合并。完全相同的替换或追加去重，互相冲突或交叠的替换使该路径失败。通过全部范围审阅的候选优先于未审阅分段草稿，即使补回非数字条件后更长，也不能只凭字节数将其淘汰。显式拒绝、无效修复、审核挂起或调用失败时，保留已经完成的分段模型结果；不以未完成审阅的全局草稿冒充核验结果。所有模型失败或只有不可解析输出时仍失败，不以原文或规则提取内容冒充模型生成的 B。

## 时间与完成性

每例使用最初接受时刻的真实截止，重复 META 只能收紧，不能续期。模型预算始终扣除 8 秒收尾，不将 70/40 秒固定为全局调用上限。

紧凑生成最多使用初始可用模型预算的 70%；分段生成到 76%，并根据队列剩余轮数分配单次请求预算；候选选择最多到 94%。分段路径完成后，最多再等待初始模型预算的 55% 争取审阅结果，同时受选择截止约束，随后取消慢请求并返回已有事实。这里的初始预算是本次开始时扣除 8 秒后的真实剩余时间，没有固定 70/40 秒的全局等待上限。

缺片时只能基于已验证范围恢复并标记缺失，不推断空白。已有部分候选时，晚到完整来源的升级最多使用剩余模型预算的一半，受独立较早截止和外层取消约束；升级失败保留已完成结果。没有部分候选时，仍允许完整来源使用剩余恢复预算。success 一旦发布，可能立即被平台锁定，不再因迟到完整来源改回 processing。

SDK 接受非空且 `finish_reason=stop` 的输出；对事实包还允许 `finish_reason=length` 但严格 JSON 校验已完整闭合的结构，不接受残缺 JSON。其他长度截断可在同一请求绝对预算内扩大上限重试一次；仅快速连接/服务失败作有限重试。成功须在 task/session 关闭、真实 Trace flush 后公布；健康检查不调用模型。

## 验证与边界

容器测试、SDK/UDP 闭环和自构文章真实模型探测的范围及最终结果见 [本地验收](local-validation.md)。模型桩只能验证工程流程；真实模型处理自构文章也不能证明官方隐藏问题 q 或总分。新候选尚无正式分，不将本地 B/A 或耗时外推为 80 分。

两端基于官方 AMD64 镜像，以非 root 启动。文章只经赛事 UDP 中继跨端传输；模型读取运行时注入的授权配置并产生真实任务调用。镜像不含文章、隐藏问题、答案、开发密钥或模型桩；不使用外部模型、模型侧信道、共享文件、特权或网络规则修改。原文若以保留前缀开头，先转义信封；最终 B 为独立可读 UTF-8 文本，不包含压缩码或信封。

下一轮正式报告应对比同文章/信道的 q、B/A、D/A、T 和成功率，尤其检查 OA03 无可锁定 B 是否消失，以及短表达是否保住 OA02 的关键事实。文章身份只用于报告诊断，不进入运行时决策。只有正式综合分改善才能确认本轮方案有效。
